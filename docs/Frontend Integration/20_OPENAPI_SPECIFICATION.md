# 20 — OpenAPI Specification

## 20.1 Why a hand-written OpenAPI is not shipped in this PR

SpringDoc / springdoc-openapi is on the classpath at version **3.2.0** (see `pom.xml` `<springdoc.version>`). The canonical, always-up-to-date OpenAPI 3.x document can be generated by the running application itself rather than maintained as a static checked-in file which would drift the moment any controller or DTO changes.

Per the assignment: if an accurate OpenAPI file can be generated without changing application behaviour, include it; otherwise state clearly that the markdown contracts are authoritative and ship guidance on how to obtain the live OpenAPI document.

This PR therefore:
1. Does **not** add a generated OpenAPI JSON/YAML file to the repository (it would be a snapshot that goes stale);
2. Documents how to retrieve the authoritative OpenAPI document from the running backend;
3. Uses the markdown contracts in §01–§14 as the reviewable human-readable reference;
4. Includes a minimal **OpenAPI skeleton** that matches the actual global contracts (envelope, security, error codes) so frontend code generators have a stable starting point — endpoint-by-endpoint path and schema detail must come from the live SpringDoc output.

## 20.2 Obtaining the authoritative OpenAPI document at runtime

With the backend running locally:

```bash
curl http://localhost:8080/v3/api-docs            # OpenAPI 3.1 JSON
curl http://localhost:8080/v3/api-docs.yaml       # OpenAPI 3.1 YAML
curl http://localhost:8080/swagger-ui/index.html  # Swagger UI (if enabled in the running profile)
```

- The `/v3/api-docs` endpoint is **public** (it is listed in the public matchers of `SecurityConfig`) so that clients and code generators can fetch it without a session; it exposes schema metadata only, never business data.
- The live output reflects:
  - All `@RestController` `@*Mapping` endpoints,
  - All `@RequestBody`, `@RequestParam`, `@PathVariable` parameters,
  - All Jakarta `@Valid` / `@NotNull` / `@Size` / etc. constraints exposed as schema constraints,
  - `@Operation` / `@Schema` descriptions where present,
  - The `ApiResponse<T>` envelope wrapper (SpringDoc resolves the generic `T` per handler return type).

**Recommended frontend workflow:** run the backend locally, pull `http://localhost:8080/v3/api-docs` into the frontend repo as a build artifact (e.g. `src/api/openapi.json`), and generate typed API clients with `openapi-typescript` / `openapi-typescript-codegen` / Orval. Regenerate whenever the backend SHA changes.

## 20.3 Global contract skeleton (OpenAPI 3.1 YAML)

This skeleton captures the cross-cutting behaviour all endpoints share (servers, security, envelope, error codes). Per-path details must come from the live `/v3/api-docs`.

```yaml
openapi: 3.1.0
info:
  title: EDAM API
  version: "4J"
  description: >
    Expense Delegation and Approval Management (EDAM). Session-cookie authentication
    with double-submit CSRF; all responses wrapped in ApiResponse<T>.
servers:
  - url: http://localhost:8080
    description: Local dev
  - url: https://{host}
    description: Per-bank deployment
    variables:
      host:
        default: edam.example.com
security:
  - sessionCookie: []   # browser-managed; all endpoints require a session except those marked public
tags:
  - name: Authentication
  - name: Users
  - name: Roles
  - name: Organization
  - name: Master Data
  - name: Expense Configuration
  - name: Approval Limits
  - name: Delegation
  - name: Committees
  - name: Workflow
  - name: Requests
  - name: Approvals
  - name: Business Rules
  - name: Documents
  - name: Communication
  - name: Configuration
  - name: Reports
  - name: Audit
  - name: Integrations
  - name: System
paths: {}      # populated from /v3/api-docs at runtime
components:
  securitySchemes:
    sessionCookie:
      type: apiKey
      in: cookie
      name: JSESSIONID
      description: >
        Session managed by Spring Security / Servlet container. The cookie is HttpOnly
        and set by POST /auth/login; the frontend must never read it. Mutating requests
        must additionally send the XSRF-TOKEN cookie value in the X-XSRF-TOKEN header
        (see csrfToken below).
    csrfToken:
      type: apiKey
      in: header
      name: X-XSRF-TOKEN
      description: >
        Double-submit CSRF token. Value is read from the readable XSRF-TOKEN cookie
        issued by GET /auth/csrf (and rotated on login/logout). Required for all
        POST/PUT/PATCH/DELETE calls.
  parameters:
    IdempotencyKeyHeader:
      name: Idempotency-Key
      in: header
      required: false
      schema:
        type: string
        format: uuid
      description: Client-generated UUID to guarantee at-most-one effect for create/action endpoints annotated @IdempotentOperation.
    BootstrapTokenHeader:
      name: X-EDAM-Bootstrap-Token
      in: header
      required: false
      schema: { type: string }
      description: Required for POST /auth/bootstrap on a fresh installation.
  schemas:
    ApiResponse:
      type: object
      required: [success, correlationId, path, timestamp]
      properties:
        success: { type: boolean }
        data: { description: "Payload on success; nullable / absent on failure or 204." }
        error: { $ref: '#/components/schemas/ErrorBody' }
        fieldErrors:
          type: array
          items: { $ref: '#/components/schemas/FieldErrorDetail' }
        correlationId: { type: string, format: uuid }
        path: { type: string }
        timestamp: { type: string, format: date-time }
    ErrorBody:
      type: object
      required: [code, message]
      properties:
        code: { type: string, example: "EDAM-2005" }
        message: { type: string, example: "You do not have permission to perform this operation." }
    FieldErrorDetail:
      type: object
      required: [field, message]
      properties:
        field: { type: string, example: "username" }
        message: { type: string, example: "must not be blank" }
    PageResponse:
      type: object
      required: [items, page, size, totalElements, totalPages, hasNext, hasPrevious]
      properties:
        items:
          type: array
          items: { }
        page: { type: integer, minimum: 0 }
        size: { type: integer, minimum: 1, maximum: 200 }
        totalElements: { type: integer, format: int64, minimum: 0 }
        totalPages: { type: integer, minimum: 0 }
        hasNext: { type: boolean }
        hasPrevious: { type: boolean }
    ErrorCode:
      type: string
      enum:
        - EDAM-1001   # VALIDATION_FAILED
        - EDAM-1002   # INVALID_REQUEST
        - EDAM-1003   # INVALID_PAGINATION
        - EDAM-1004   # IDEMPOTENCY_CONFLICT
        - EDAM-1005   # IDEMPOTENCY_IN_PROGRESS
        - EDAM-1006   # IDEMPOTENCY_UNKNOWN_OUTCOME
        - EDAM-2001   # UNAUTHENTICATED
        - EDAM-2002   # ACCESS_DENIED
        - EDAM-2003   # INSTITUTION_REQUIRED
        - EDAM-2004   # INSTITUTION_ACCESS_DENIED
        - EDAM-2005   # PERMISSION_DENIED
        - EDAM-2006   # INVALID_CREDENTIALS
        - EDAM-2007   # ACCOUNT_LOCKED
        - EDAM-2008   # WEAK_PASSWORD
        - EDAM-2009   # INVALID_RESET_TOKEN
        - EDAM-2010   # INSTALLATION_ALREADY_COMPLETED
        - EDAM-2011   # INSTALLATION_NOT_BOOTSTRAPPED
        - EDAM-3001   # BUSINESS_RULE_VIOLATION
        - EDAM-3002   # CONCURRENT_MODIFICATION
        - EDAM-3003   # PRECONDITION_FAILED
        - EDAM-3004   # INVALID_STATE_TRANSITION
        - EDAM-3005   # SYSTEM_ROLE_PROTECTED
        - EDAM-4001   # NOT_FOUND
        - EDAM-5001   # PERSISTENCE_ERROR
        - EDAM-5002   # DUPLICATE_RESOURCE
        - EDAM-5003   # EXTERNAL_SERVICE_FAILURE
        - EDAM-5004   # INVALID_DOCUMENT
        - EDAM-5005   # INVALID_CONFIGURATION
        - EDAM-9001   # INTERNAL_ERROR
  responses:
    BadRequest:
      description: Validation or malformed request
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/ApiResponse'
    Unauthorized:
      description: Session required / invalid credentials / locked
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/ApiResponse'
    Forbidden:
      description: Permission denied or CSRF failure
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/ApiResponse'
    NotFound:
      description: Resource does not exist or is not visible to caller
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/ApiResponse'
    Conflict:
      description: Business/state/concurrency conflict
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/ApiResponse'
    InternalError:
      description: Unexpected error
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/ApiResponse'
```

## 20.4 Generating typed TypeScript clients
Recommended tool: **openapi-typescript** + a small hand-written fetch wrapper (or **Orval** which can output React Query hooks). Because the backend uses cookie auth, do NOT generate bearer-token interceptors. Example using `openapi-typescript`:

```bash
curl http://localhost:8080/v3/api-docs -o src/api/openapi.json
npx openapi-typescript src/api/openapi.json -o src/api/schema.d.ts
```

Then use `paths` from the generated `paths` interface for fully-typed requests; keep the custom `api<T>()` wrapper from §04 to handle CSRF, credentials and error normalization.
