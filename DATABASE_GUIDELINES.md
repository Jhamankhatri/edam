# Database Guidelines — PostgreSQL, Flyway & JPA

## 1. Core Persistence Philosophy (`OBJ-09`, BRD Sec 15.2)

- **Business logic lives in Java domain/application services**; PostgreSQL is responsible for ACID transactions, normalized relational modeling, foreign keys, check constraints, unique constraints, and query indexes.
- **Zero stored procedures**: Legacy SQL Server stored procedures are not recreated in PostgreSQL; business rules are extracted, tested in Java, and executed inside `@Transactional` service boundaries.
- **No production auto-DDL**: `spring.jpa.hibernate.ddl-auto` is `validate` across **all** environments (`application.yml`), ensuring Hibernate strictly validates entities against Flyway-managed tables.
- **No Open-Session-in-View**: `spring.jpa.open-in-view` is `false` so all lazy associations required for rendering or DTO mapping are explicitly fetched inside `@Transactional` service calls.

---

## 2. Flyway Migration Rules

- Location: `src/main/resources/db/migration/`
- Naming: `V<version>__<snake_case_description>.sql` (e.g., `V1__foundation_schema.sql`, `V2__platform_permissions.sql`).
- **Immutability**: Once a migration script is committed/applied to any shared environment, never modify it — create a new `V<next>__...sql` migration instead.
- **Phase 1 Boundaries**: Only foundation tables exist (`institutions`, `institution_branding`, `institution_settings`, `users`, `permissions`, `roles`, `role_permissions`, `user_institution_memberships`, `user_institution_roles`, `audit_events`). OPEX/CAPEX, workflow, committee, and delegation matrix tables are deferred to Phases 2–4 pending BRD sign-off (`OD-01`–`OD-22`).
- **Environment-Specific Migrations**: Never embed client-specific production users, passwords, or bank branding inside `db/migration/`; use environment provisioning or secure admin APIs.

---

## 3. Schema & JPA Mapping Standards

1. **Identity Columns**: Use PostgreSQL `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` paired with `@GeneratedValue(strategy = GenerationType.IDENTITY)`.
2. **Timestamps**: Use `TIMESTAMPTZ` in PostgreSQL paired with `java.time.Instant` in Java, with Hibernate JDBC time zone fixed to `UTC`.
3. **Auditing Columns**: Mutable tables extend `AuditableEntity` (`created_at`, `updated_at`, `created_by`, `updated_by`, `version`) populated by `SpringSecurityAuditorAware` and guarded by `@Version` optimistic locking.
4. **Immutable Audit Events**: `audit_events` is append-only (`occurred_at` without `updated_at` or `version`).
5. **Hibernate 7 + Jackson 3 Compatibility**: Hibernate 7 does not auto-wire a Jackson 3 `FormatMapper` by default; store structured audit snapshots as `TEXT` (`columnDefinition = "text"`) or serialize explicitly via `tools.jackson.databind.json.JsonMapper`.
6. **Monetary Columns (Phase 2+)**: Always use `NUMERIC(19, 4)` (or BRD-approved scale) paired with `java.math.BigDecimal` — never `float` or `double`.
7. **Avoiding Hibernate `MultipleBagFetchException`**: Use `Set<T>` for `@ManyToMany` collections fetched together via `JOIN FETCH` (as implemented in `Role.permissions` and `UserInstitutionMembership.roles`).
8. **Foreign Key Delete Guards**: Prefer `ON DELETE RESTRICT` for business and tenant parent foreign keys so referenced institutions, users, or permissions cannot be deleted silently.
9. **Case-Insensitive Lookups**: Pair functional expression indexes (`ON institutions (LOWER(code), status)`, `ON users (LOWER(username))`) with repository queries (`findByCodeIgnoreCaseAndStatus`, `findByUsernameIgnoreCase`).
